# การ์ดสถานการณ์ทดสอบผู้ใช้จริง

ผู้ดำเนินการอ่านเฉพาะข้อความในกรอบของ task ที่กำหนด ห้ามอ่านส่วน fixture หรือบอกข้อมูลที่ไม่ได้อยู่ในการ์ด การ์ดเป็นสถานการณ์และเป้าหมาย ไม่ใช่คู่มือ

## TC1 — ผู้ใช้หาห้องสอบและไปยังห้อง

> คุณต้องไปสอบวิชา BAS350 เวลา 13:00–16:00 น. แต่คุณยังไม่ทราบว่าต้องสอบที่ห้องใด โปรดหาห้องสอบที่ถูกต้องและไปให้ถึงห้องนั้น

**บันทึกภายในสำหรับผู้ดำเนินการ — ห้ามอ่านให้ผู้ทดสอบฟัง**

- course code และเวลาอิงรายการจริงใน [lc3-schedules.seed.json](../../tools/data-extraction/lc3/lc3-schedules.seed.json): BAS350, 13:00–16:00, `event_type: exam`
- seed ปัจจุบันมี `event_date: 2026-05-18`, `room_code: LC3-103`; วันที่นี้ผ่านไปแล้วก่อนรอบทดสอบ จึงต้องใช้ fixture ใน personal dev test stack ที่ค้นหาได้ในวันทดสอบ และห้ามแสดงห้องให้ผู้ทดสอบก่อนเริ่ม ดูรายละเอียดใน [test-fixtures.md](./test-fixtures.md)
- ตรวจว่าผลของ #146 แสดงวัน/เวลา/ห้องและเปิดการนำทางไปปลายทางได้จริงก่อนใช้การ์ด
- ห้ามเปลี่ยน seed ที่สร้างจาก generator หรือข้อมูล production เพื่อให้ผ่าน task

## TC2 — Staff ย้ายกิจกรรมและปิดทางเดินชั่วคราว

> กิจกรรม **ประชุมแผนงาน V4** ที่ห้องประชุม **LC3-225** วันที่ **30 ต.ค. 2026** เวลา **13:00–14:00 น.** ต้องย้ายไป **LC3-227** และ **[ชื่อช่วงทางเดินที่ยืนยันจากแผนที่ทดสอบ]** ต้องปิดชั่วคราวตั้งแต่ **12:30 น.** ถึง **14:30 น.** ด้วยเหตุผลบำรุงรักษาทางเดิน โปรดปรับข้อมูลให้ผู้เข้าร่วมได้รับข้อมูลสถานที่และเส้นทางที่ถูกต้อง

**บันทึกภายในสำหรับผู้ดำเนินการ — ห้ามอ่านให้ผู้ทดสอบฟัง**

- ใช้กิจกรรมทดสอบที่สร้างใน personal dev test stack แยกจากข้อมูลจริง; กรอกเฉพาะชื่อช่วงทางเดินในวงเล็บเหลี่ยมหลัง #146/#147 พร้อมใช้งานและตรวจ fixture แล้ว
- fixture ที่เสนอ: `ประชุมแผนงาน V4`, ห้องเดิม `LC3-225` (ห้องประชุมใน location seed), ห้องใหม่ `LC3-227`, วันที่ `2026-10-30`, เวลา `13:00–14:00`, ปิดตั้งแต่ `12:30–14:30` และเหตุผล `บำรุงรักษาทางเดิน (ข้อมูลทดสอบ)`
- ยืนยันชื่อ/ตำแหน่งช่วงทางเดินจากแผนที่ใน build ที่จะทดสอบก่อนพิมพ์การ์ดจริง; หาก route เดิม/route หลังปิดไม่เป็นไปตามที่คาด ให้เลือก fixture ทางเดินใหม่และทดสอบซ้ำก่อน session
- ตั้งต้นให้กิจกรรมอยู่ห้องเดิมและทางเดินเปิด; ผู้ทดสอบ staff ต้องเป็นผู้ทำการเปลี่ยนแปลงเอง
- ปิดเฉพาะช่วงทางเดินที่ผู้ดำเนินการทดสอบแล้วว่า route เดิมใช้ผ่าน และมีทางเลือกที่ปลอดภัยไปยังห้องใหม่
- ระบุวัน/เวลาของกิจกรรมและช่วงปิดเป็นเวลาท้องถิ่น `Asia/Bangkok`; ตรวจเทียบเวลาในระบบก่อน session
- ห้ามกรอกชื่อปุ่ม, ชื่อแท็บ, ลำดับการกระทำ หรือคำแนะนำการใช้งานในวงเล็บ

## TC2 — ผู้เข้าร่วมค้นหากิจกรรมและไปยังสถานที่จริงหลังเปลี่ยนแปลง

> คุณกำลังจะเข้าร่วมกิจกรรม **ประชุมแผนงาน V4** วันที่ **30 ต.ค. 2026** เวลา **13:00–14:00 น.** คำเชิญเดิมระบุสถานที่เป็น **ห้อง LC3-225** คุณยังไม่ทราบว่ามีการเปลี่ยนแปลงสถานที่หรือเส้นทางหรือไม่ โปรดหาข้อมูลที่ถูกต้องและไปให้ถึงสถานที่จัดกิจกรรม

**บันทึกภายในสำหรับผู้ดำเนินการ — ห้ามอ่านให้ผู้ทดสอบฟัง**

- ใช้ fixture `ประชุมแผนงาน V4`, `LC3-225` → `LC3-227`, `2026-10-30 13:00–14:00` เดียวกับ TC2 staff หลัง staff ทำการเปลี่ยนแปลงเสร็จ ห้าม reset ระหว่างสอง task
- ข้อความไม่บอกห้องใหม่หรือทางเดินที่ปิด
- ตรวจว่าการค้นหากิจกรรมแสดงตำแหน่งใหม่และ route เลี่ยง closure ก่อนเริ่ม session
- ถ้าผู้ทดสอบทราบคำตอบจากการดู TC2 staff ก่อนหน้า ให้บันทึกเป็น prior exposure; ใช้ผู้เข้าร่วมคนละคนสำหรับสอง role หากต้องการวัดการค้นพบแบบไม่ทราบข้อมูล
