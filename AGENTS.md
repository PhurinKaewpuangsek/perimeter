# Agent Guidelines: Perimeter

> Stop and ask the human if a request conflicts with these rules.

## Non-Negotiables
- **Branch first.** Never commit or push directly to `main`.
- **Trace every branch to a GitHub Issue.** (Issue → branch → PR).
- **PR to `main`.** Green CI and CodeRabbit review required (all inline comments must be resolved). *Exception: If CodeRabbit runs out of tokens, you may skip its review.*
- **Human authorship default.** Do not add AI footers, co-authors, or "Generated by AI" unless the human explicitly asks for it.
- **Require Explicit Authorization.** Never `git commit`, `git push`, or `gh pr create` on your own. You must pause and ask the human for authorization first so they can review the changes, even if running with `--dangerously-skip-permissions`.
- **No secrets.** Keep `.env` local; track only `.env.example`.
- **Leave workflows alone.** Do not edit `.github/workflows/` unless explicitly requested or required for Pipeline Parity when introducing new stack outputs.

## Architecture (V4)
Perimeter is a serverless indoor navigation and timetable information service mapping cloud data onto interactive 2D SVG and 3D floor plans with shortest-path routing, temporary walkway/room closures, exam search, and authenticated user schedule pinning. (Legacy CloudFormation resources retain the `Torch` prefix, e.g., `TorchUserPool`).
- **Frontend**: React 18 + Vite + TypeScript + Tailwind + Three.js (`frontend/`)
- **Routes**: `/` (landing), `/login` (unified sign-in & password challenge), `/map` (floor plan, routing & My Schedule), `/staff` (room/schedule editor & closure manager), `/admin` (user management)
- **Backend**: AWS Lambda (Node.js 24) (`functions/<name>/`) via Implicit API Gateway with Cognito User Pool Authorizer on write routes. Public read endpoints include `/api/locations`, `/api/schedules`, `/api/graph`, and `/api/route` (planned); protected endpoints include `/api/pins`, `/api/users`, and `/api/graph/closures` (planned).
- **Auth**: AWS Cognito User Pool with groups (`admin`, `staff`, `user`)
- **Database**: Amazon DynamoDB (on-demand: `SmartFacultyLocations`, `SmartFacultySchedules`, `SmartFacultyPins`, `SmartFacultyGraph`)
- **Infrastructure**: AWS SAM (`template.yaml` at repo root)

## Directory Boundaries
- `frontend/`: React client. Own `package.json`.
- `functions/<name>/`: Lambda handlers. Each function has its own `package.json`. No relative cross-directory imports to `frontend/`.
- `tools/`: Data extraction and seed scripts.
- `template.yaml`: AWS SAM definition.

## Infrastructure Rules (AWS SAM, No ClickOps)
- **No ClickOps**: Manage all cloud resources via `template.yaml`. Never create or edit resources via the AWS Console.
- **DynamoDB**: Use `AWS::DynamoDB::Table` (on-demand). Do not delete attributes actively read by consumers.
- **API Gateway**: Implicit. Declare Lambda API events using `Type: Api` without `RestApiId`. Never create a separate `AWS::Serverless::Api` resource.
- **CORS**: Lambda responses must include `"Access-Control-Allow-Origin": "*"` in headers.

## Production Parity & New Service Additions
When introducing a new AWS service, resource, or client configuration:
- **IAM Least Privilege**: Declare all Lambda IAM permissions explicitly in `template.yaml` (under function `Policies` or dedicated IAM role). Never rely on ambient lab admin rights; verify that least-privilege roles suffice for the production pipeline.
- **Stack Outputs Contract**: Expose new resource identifiers (IDs, ARNs, endpoints) in `template.yaml` `Outputs:`.
- **Pipeline Parity (Four-Point Sync)**: Whenever the frontend or client consumes a new CloudFormation output or env var:
  1. Expose it in `template.yaml` `Outputs:`.
  2. Update `scripts/write-env.mjs` for local development.
  3. Update `.github/workflows/cd-frontend.yml` (in `Fetch CloudFormation Outputs` and `env:`) so the production S3 build receives it.
  4. Update `frontend/.env.example`.

## Workflow
- **Trunk-based development**: Short-lived branches off `main`. Squash merge and delete.
- **Conventional Commits**: `<type>(<optional-scope>): <imperative message> (#<issue>)`.
- **PR Titles & Squash Merges**: PR titles must follow Conventional Commits. When squash merging a PR into `main`, ensure the final commit message includes the PR number (e.g., `(#<pr-number>)`) to track the merged PR.
- **Agent Playbook**:
  1. Sync trunk (`git pull --ff-only origin main`).
  2. Branch using exact name from the issue blockquote (`Set Branch Name as:`).
  3. Work in atomic commits. Stage only touched files.
  4. Verify authorship (`git log origin/main..HEAD --pretty=fuller`) shows zero AI attribution.
  5. Ask the human for permission before committing, pushing, or opening a PR.
  6. Open PR into `main` with green CI. A human merges.
